# Экспериментальный адаптер для Claude Code

Адаптер переводит запросы Claude Code из формата Anthropic Messages в формат OpenAI, который принимает сторонний `hoplite-gateway`. Простая подмена адреса не решает несовместимость протоколов: Claude Code ожидает Anthropic Messages, а шлюз предоставляет OpenAI-совместимый API.

```text
Claude Code → адаптер http://127.0.0.1:8788 → hoplite-gateway http://127.0.0.1:8787/v1 → облако Hoplite
```

Это экспериментальная связка, а не официальный или полностью совместимый с Claude Code шлюз. Репозиторий `hoplite-gateway` сторонний, не включён в этот проект и не проверяется и не запускается адаптером автоматически. Ознакомьтесь с его исходным кодом и документацией до использования.

## Что поддерживает адаптер

- `POST /v1/messages`: принимает запросы Anthropic Messages и передаёт их в OpenAI-совместимый шлюз.
- Потоковый ответ Anthropic SSE: пока адаптер ждёт **полный** ответ шлюза, он посылает SSE-события `ping`; токены в реальном времени не передаются.
- `GET /v1/models`: список моделей для клиента.
- `GET /health`: проверка жизни самого адаптера, **не** готовности шлюза, Hoplite или всего пути запроса.
- `POST /v1/messages/count_tokens` возвращает HTTP `501 Not Implemented`: точный подсчёт у этого шлюза недоступен. Адаптер не подменяет его выдуманным значением.

Вызовы инструментов эмулируются шлюзом через текстовый протокол в запросе, а не обеспечиваются полноценным нативным циклом инструментов Anthropic. Шлюз может обрезать историю диалога, результаты инструментов и схемы инструментов; он также может использовать облачные инструменты или модель-резерв проекта. Поэтому этот адаптер сам по себе **не гарантирует**, что инструменты будут выполняться только на вашем компьютере.

Изображения, PDF, thinking-блоки в истории, структурированный вывод по JSON-схеме и серверные инструменты не поддерживаются и отклоняются. Для совместимости с Claude Code 2.1.283 настройки `thinking.type: enabled/adaptive` принимаются, но не передаются upstream: подписанные thinking-блоки не возвращаются, `budget_tokens` не применяется. Это режим совместимости, а не реализация Anthropic extended thinking. `output_config.effort` независимо переводится в `reasoning_effort` шлюза. Совместимость с Claude Code неполная и может зависеть от изменений его API и стороннего шлюза. Использование шлюза может сообщать нулевое число использованных токенов, даже если запрос был обработан. Сам шлюз может игнорировать `max_tokens`, параметры семплирования и `tool_choice`; ограничения Anthropic API не гарантируются. Сообщения, объединяющие результаты инструментов с новым пользовательским текстом, могут терять результаты на стороне шлюза.

Настройки `context_management.edits` с типами `clear_tool_uses_20250919`, `clear_thinking_20251015` и `compact_20260112` принимаются для совместимости с новыми клиентами, но не применяются и не передаются gateway. Адаптер сохраняет присланную историю и не возвращает `applied_edits` или блоки compaction. Это не серверное управление контекстом Anthropic: пороги очистки, сохранение thinking и `pause_after_compaction` здесь не действуют. Ограничения и обрезка истории самого gateway остаются. Неизвестные стратегии и некорректная структура отклоняются.

## Требования

- Python 3.10 или новее.
- Установленный и доступный в `PATH` Claude Code для команды `claude`.
- Отдельно установленный и запущенный `hoplite-gateway` на `http://127.0.0.1:8787`.

## Linux: только Claude Code, шлюз на сервере

Для этого режима нужен **работающий HTTPS-адрес адаптера и отдельный токен адаптера**. Публикация кода на GitHub не запускает сервер. В этой поставке готового облачного адреса пока нет; рабочая среда Hoplite может засыпать и не является постоянным хостингом.

Скачать опубликованную ветку (нужны Git, Python 3.10+ и установленный `claude`):

```bash
git clone --branch hoplite/pharsalos-496287b4 --single-branch https://github.com/adeptoxygen/cxzcxz.git hoplite-claude
```

После получения адреса и токена один раз настройте клиент:

```bash
python3 hoplite-claude/client.py configure
```

Токен вводится скрыто и сохраняется в `~/.config/hoplite-claude/client.json` с правами `600` (либо в `$XDG_CONFIG_HOME/hoplite-claude/client.json`). Это **не ключ Hoplite**. Клиенту не нужны pip, venv, ngrok или локальный gateway. В URL не добавляйте `/v1`.

Из папки своего проекта запускайте:

```bash
python3 /полный/путь/hoplite-claude/client.py run
# или разовый запрос:
python3 /полный/путь/hoplite-claude/client.py run -- -p 'Объясни структуру проекта'
```

Для временного размещения сервера оператору нужны защищённые переменные `HOPLITE_API_KEY`, `HOPLITE_PROJECT_ID`, `NGROK_AUTHTOKEN`. Само их добавление не запускает сервис: gateway, адаптер и HTTPS-туннель нужно настроить и проверить отдельно. Не пересылайте эти значения в чат и не публикуйте административный интерфейс gateway. Для круглосуточного доступа нужен постоянный сервер, а не рабочая среда этого треда.

### Временный сервер в рабочей среде Hoplite

`hosting.py setup` устанавливает зависимости через `uv`, загружает отдельный `server.py` стороннего gateway и официальный ngrok для Linux x86-64 в игнорируемую папку `.hoplite/runtime`. Загруженный gateway сохраняется между запусками; его обновление не выполняется автоматически. При первой установке используется текущая ветка upstream, не фиксированная версия — проверяйте исходный код перед передачей ему ключа.

Оператор хранит `hoplite_api_key`, `project_id`, `ngrok_authtoken` в приватном `.hoplite/runtime/hosting-secrets.json` с правами `600`. Этот файл не публикуется. `hosting.py run` создаёт раздельные токены gateway/адаптера и управляет всеми тремя процессами; завершение любого процесса останавливает остальные. Только адаптер публикуется через туннель, просмотр содержимого запросов в ngrok отключён. При необходимости поле `ngrok_url` задаёт другой разрешённый вашему аккаунту HTTPS-домен.

Проектные команды для управляемого запуска: setup — `python3 hosting.py setup`, run — `exec .venv/bin/python hosting.py run`. Приватные настройки не переносятся автоматически в новую рабочую среду. Логи находятся в `.hoplite/runtime/*.log`, не публикуйте их без очистки.

**`ERR_NGROK_334` означает, что домен уже занят другим туннелем.** Остановите именно тот туннель в своём ngrok Dashboard либо укажите другой разрешённый домен. Не используйте `--pooling-enabled` для обхода этой ошибки: это направит часть запросов в другой сервис. Пока ошибка не устранена, публичного API нет. Проверка ключа Hoplite через `/api/projects` сама по себе не подтверждает работу ответов модели.

## Linux: локальный адаптер (альтернативный режим)

Если сервер ещё не размещён, можно запустить всю связку у себя:

```bash
cd hoplite-claude
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python adapter.py init
# Настройте и запустите отдельный gateway, как описано ниже.
# В config.json адаптера задайте upstream_api_key = gateway_key шлюза.
.venv/bin/python adapter.py serve
```

В другом терминале: `/полный/путь/hoplite-claude/.venv/bin/python /полный/путь/hoplite-claude/adapter.py claude`.

## Установка адаптера в Windows PowerShell

Выполняйте команды из папки этого проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Инициализируйте локальную конфигурацию, затем запустите адаптер:

```powershell
python adapter.py init
python adapter.py serve
```

`init` копирует значения по умолчанию в локальный `config.json` и создаёт случайный локальный токен аутентификации. Этот токен **не является** ключом Hoplite. Файл `config.json` игнорируется Git — не добавляйте его в коммиты и не отправляйте секреты в чат.

После запуска адаптера откройте второе окно PowerShell, перейдите в папку проекта, активируйте окружение и передайте аргументы установленному Claude Code:

```powershell
.\.venv\Scripts\Activate.ps1
python adapter.py claude
```

Для одноразового запроса: `python adapter.py claude -- -p "Объясни структуру проекта"`. Команда запускает установленный `claude` с `ANTHROPIC_BASE_URL`, указывающим на локальный адаптер, и `ANTHROPIC_AUTH_TOKEN`, содержащим локальный токен из `config.json`. Все стандартные псевдонимы моделей направляются на модель из конфигурации адаптера; thinking отключён. Переменные действуют только в дочернем процессе, глобальные настройки Claude Code не изменяются. Штатные подтверждения и разрешения сохраняются: не добавляйте `--dangerously-skip-permissions`.

Claude Code работает в текущей папке. Для работы с другим проектом перейдите в него и запустите адаптер по абсолютному пути:

```powershell
Set-Location C:\path\to\your-project
& C:\path\to\adapter\.venv\Scripts\python.exe C:\path\to\adapter\adapter.py claude
```

На Linux/macOS используйте `python3 -m venv .venv`, `source .venv/bin/activate`, затем те же команды `python -m pip install -r requirements.txt` и `python adapter.py …`.

## Отдельная установка hoplite-gateway

Эти команды только клонируют сторонний репозиторий в отдельную папку; адаптер не делает этого за вас. В PowerShell:

```powershell
$GatewayDir = Join-Path $HOME 'hoplite-gateway'
git clone https://github.com/nikita4a/hoplite-gateway.git $GatewayDir
Set-Location $GatewayDir
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item config.example.json config.json
```

Откройте `README.md` и `config.example.json` в этой папке, проверьте инструкции актуальной версии шлюза и внесите значения в его локальный `config.json`. Для запуска, согласно README шлюза, используется `python server.py`; шлюз должен слушать `127.0.0.1:8787`. Не запускайте его с публичным интерфейсом и не открывайте наружу административный интерфейс.

Настройте **разные** секреты для разных назначений:

| Параметр шлюза | Значение |
| --- | --- |
| `api_key` | Новый ключ Hoplite, созданный для этой интеграции. Он предназначен для доступа шлюза к Hoplite; не используйте вместо него локальный токен адаптера или `gateway_key`. |
| `project_id` | Явный идентификатор отдельного выделенного проекта Hoplite. Не полагайтесь на неявный проект по умолчанию. |
| `gateway_key` | Отдельный случайный токен для доступа адаптера к шлюзу. Проверенная при разработке версия `server.py` поддерживает его для `/v1/*`. |

Сгенерировать отдельный `gateway_key` локально: `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Скопируйте результат только в два локальных конфига.

В конфигурации адаптера установите `upstream_api_key` равным тому же значению `gateway_key`. Не используйте ключ Hoplite в качестве ключа шлюза или адаптера. Создайте ключ Hoplite самостоятельно в официальном интерфейсе; не вставляйте его в этот README, коммиты или чат. Не используйте браузерные cookies для аутентификации.

## Конфигурация адаптера

После `python adapter.py init` отредактируйте `config.json`:

| Поле | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `host` | `127.0.0.1` | Интерфейс прослушивания; оставляйте локальным для обычного запуска на одном компьютере. |
| `port` | `8788` | Порт адаптера. |
| `upstream_url` | `http://127.0.0.1:8787/v1` | Адрес OpenAI-совместимого API шлюза. |
| `upstream_api_key` | пустая строка | Тот же секрет, что и `gateway_key` шлюза. Заполните перед запросами, если шлюз требует этот ключ. |
| `model` | `hoplite-agent` | Имя модели, передаваемое шлюзу для всех стандартных псевдонимов Claude Code. |
| `auth_token` | генерируется при `init` | Случайный локальный токен, который команда `claude` передаёт адаптеру. Не заменяйте его ключом Hoplite. |
| `timeout_seconds` | `300` | Максимальное время ожидания ответа шлюза. |

Храните `config.json` только локально. Не публикуйте ключи и не вставляйте их в переписку. Если секрет попал в общий доступ, отзовите и замените его.

## Проверки

Запуск модульных тестов проекта:

```powershell
python -m unittest discover -s tests -v
```

Перед тестами установите `python -m pip install -r requirements-dev.txt`. Дополнительный тест с установленным Claude Code: `python tests/smoke_cli.py`; вариант с отдельным клиентом: `python tests/smoke_cli.py --remote-client`. Он использует подставной upstream, временный файл и разрешает только инструмент `Read`; ключ Hoplite не требуется.

При разработке проверен полный цикл с Claude Code **2.1.233 и 2.1.283** на подставном upstream: запрос → `tool_use` → локальное чтение файла → `tool_result` → финальный ответ, а также разбор SSE официальным Anthropic SDK. Claude Code **2.1.283** также успешно выполнил простой текстовый запрос через публичный адаптер к настоящему Hoplite. Прямой живой SSE-запрос с `context_management` и thinking вернул полный ответ без ошибки. Запуск на Windows и полный цикл локальных инструментов с настоящим Hoplite **не проверены**. Для проверки своей цепочки запустите шлюз и адаптер, затем `python adapter.py claude -- -p "Ответь одним словом: готово"`; это может расходовать кредиты Hoplite.

При `401` проверьте, какой участок отклонил токен: локальный `auth_token`, общий `gateway_key`/`upstream_api_key` или ключ Hoplite в шлюзе. При `502` убедитесь, что шлюз запущен. После `504` облачный запуск может продолжать работать — проверьте его в Hoplite перед повтором. Остановка локального запроса не гарантирует остановку облачного агента.

## Доступ из сети

Если Claude Code работает на том же компьютере, ngrok не нужен: используйте локальные адреса `127.0.0.1`. Если внешнему клиенту действительно требуется доступ, наружу можно направить только адаптер через HTTPS-туннель и отдельный случайный токен адаптера. Не публикуйте шлюз или его административные маршруты. Публичный развёртываемый вариант здесь не описан и не проверен.

Документация upstream может отставать от кода: его README описывает клиентский API-ключ как произвольное значение, но проверенный `server.py` поддерживает `gateway_key`. Этот проект не запрашивает и не рекомендует браузерные cookies. Если API-ключ не позволяет продолжать диалог, решите вопрос с разрешениями через официальный API, а не копированием браузерной сессии. Возможности шлюза определяются его конкретной версией, а не адаптером.
